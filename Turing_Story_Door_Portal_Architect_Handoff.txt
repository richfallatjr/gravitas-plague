Turing Story Door Portal Architect Handoff
==========================================

Goal
----
Add a Story-mode door portal bundle based on the current Story window portal MVP, but with door-style floor snapping like the Horde/Hell portal path.

The door should:

- Load a USDZ door bundle.
- Mount to a detected wall.
- Snap the door bottom to the detected floor.
- Use the same portal workflow as the Story window.
- Use the Horde/Hell portal ground-disc methodology and height.
- Use the same day/night environment state controlled by the poster day/night icon.
- Support the same occlusion-plane workflow as the shelf/window bundles.
- Avoid overlap with the poster, walkie shelf bundle, Story window bundle, and Horde/Story portals.

This is a handoff for implementation. It intentionally does not change Qwen, audiobook, playback, filler, prompts, or TTS scheduling.


Non-Goals
---------
- Do not touch Qwen generation.
- Do not touch Big Mike clone artifacts.
- Do not touch audiobook source sectioning.
- Do not touch Story/Turing playback.
- Do not add a new day/night toggle if the poster day/night icon already exists.
- Do not add a separate occlusion system. Match the current glyph/window/shelf occlusion material behavior.
- Do not use the window ground offset for the door. The door ground disc should be at Horde portal ground-disc height.

Door Placement Shape
--------------------
Prefer reusing the existing DoorPlacement floor-lock model rather than inventing a second floor-lock math path.

Recommended wrapper:

  struct TuringStoryDoorBundlePlacement: Codable, Equatable, Sendable {
      var doorPlacement: DoorPlacement
      var worldYawRadians: Float
  }

Factory:

  extension TuringStoryDoorBundlePlacement {
      static func defaultForWall(_ wall: WallCandidate) -> TuringStoryDoorBundlePlacement {
          var placement = DoorPlacement.defaultForWall(wall)
          placement.width = TuringStoryDoorBundleTuning.defaultWidthMeters
          placement.height = TuringStoryDoorBundleTuning.defaultHeightMeters
          placement.depthOffset = TuringStoryDoorBundleTuning.depthOffset
          placement.bottomClearance = TuringStoryDoorBundleTuning.bottomClearanceMeters
          placement.floorLocked = true
          placement.confirmed = true
          return TuringStoryDoorBundlePlacement(
              doorPlacement: placement,
              worldYawRadians: 0
          )
      }
  }


Floor Snap Requirement
----------------------
The door must not silently float if floor data is missing.

Use required floor lock:

  guard var resolved = wallManager.resolveFloorLockedPlacement(
      placement,
      requirement: .required
  ) else {
      print("[TuringDoorPortal] floor lock unavailable; placement deferred")
      return nil
  }

Then:

  guard let transform = wallManager.convertWallLocalToWorldTransform(placement: resolved) else {
      print("[TuringDoorPortal] placement transform unavailable")
      return nil
  }

  doorRoot.setTransformMatrix(transform, relativeTo: nil)

Add proof logging:

  private func logDoorFloorProof(
      placement: DoorPlacement,
      wallManager: WallPlaneManager
  ) {
      guard
          let wall = wallManager.wallCandidate(id: placement.wallID),
          let floorWorldY = placement.floorWorldY
      else {
          print("[TuringDoorPortal] floor proof unavailable")
          return
      }

      let bottomCenter =
          wall.center +
          wall.right * placement.localX +
          wall.up * (placement.localY - placement.height * 0.5) +
          wall.normal * placement.depthOffset

      print("[TuringDoorPortal] floor lock proof")
      print("  bottomWorldY: \(bottomCenter.y)")
      print("  floorWorldY: \(floorWorldY)")
      print("  bottomClearance: \(bottomCenter.y - floorWorldY)")
      print("  expectedBottomClearance: \(placement.bottomClearance)")
  }

Acceptance:

- bottomWorldY - floorWorldY should be approximately 0.015 m.
- A tolerance around 0.02 m is acceptable for MVP.
- If no floor candidate exists, do not place; retry when floor detection updates.

Door Portal Content Provider
----------------------------
Clone the Story window provider, but replace the window ground-disc offset with the Horde portal ground height.

Required behavior:

- Add WorldComponent to portalWorld.
- Install native bloom like the window.
- Reuse the same day/night HDRI dome logic as the window.
- Disable the HDRI provider's own ground disc.
- Add a Horde-style feathered ground disc at context.floorY + 0.004.
- Use the Story day/night ground textures already used by the window.
- Rotate the HDRI/dome by worldYawRadians for multi-window/multi-door support.

Code:

  struct TuringStoryDoorPortalContentProvider: PortalContentProvider {
      static let providerID = "turingStoryDoorDayNight"

      let atmosphere: PortalHDRIAtmosphere
      let worldYawRadians: Float

      @MainActor
      func populatePortalWorld(
          portalWorld: Entity,
          context: PortalContentContext
      ) async throws {
          portalWorld.children.removeAll()
          portalWorld.components.set(WorldComponent())
          PlagueNativeBloomInstaller.installStrictBloom(on: portalWorld)

          let hdriProvider = HDRIDomePortalContentProvider(atmosphere: atmosphere)
          try await hdriProvider.populatePortalWorld(
              portalWorld: portalWorld,
              context: PortalContentContext(
                  doorWidth: context.doorWidth,
                  doorHeight: context.doorHeight,
                  floorY: context.floorY,
                  groundDiscEnabled: false,
                  groundDiscRadius: context.groundDiscRadius,
                  groundDiscCenterZ: context.groundDiscCenterZ
              )
          )

          let ground = try HordePortalGroundDiscFactory.makeGroundDisc(
              config: HordePortalGroundDiscFactory.Config(
                  floorY: context.floorY + 0.004,
                  centerZ: context.groundDiscCenterZ,
                  radius: context.groundDiscRadius,
                  segments: 96,
                  featherRingCount: 8,
                  featherStartFraction: 0.72,
                  textureName: groundTextureName(for: atmosphere),
                  exposure: atmosphere.visibleExposure
              )
          )
          portalWorld.addChild(ground)

          if let backdrop = portalWorld.findEntity(
              named: "PortalHDRIDome_\(atmosphere.exrResourceName)"
          ) {
              backdrop.orientation *= simd_quatf(
                  angle: worldYawRadians,
                  axis: SIMD3<Float>(0, 1, 0)
              )
          }

          print("[TuringDoorPortal] portal world populated")
          print("  atmosphere: \(atmosphere)")
          print("  groundFloorY: \(context.floorY + 0.004)")
          print("  groundMode: horde_feathered_disc")
      }

      private func groundTextureName(for atmosphere: PortalHDRIAtmosphere) -> String {
          switch atmosphere {
          case .overcast:
              return "day-groundplane-tile"
          case .night:
              return "night-groundplane-tile"
          }
      }
  }

If the project enum names differ, use the exact names from the current Story window provider.


Ground Disc Height Rule
-----------------------
This is the most important behavioral difference from the window.

Window currently uses:

  context.floorY - 2.5 ft

Door must use Horde portal height:

  context.floorY + 0.004

Reason:

- The window is an elevated view and needed a visual offset.
- The door represents an opening to a floor-level exterior.
- Its exterior ground should sit at the portal world's floor, like the Horde/Hell portal.

Day/Night Toggle
----------------
Do not add a second day/night control for the door if the poster day/night icon exists.

Use the existing poster day/night icon under the RealityKit poster:

- Day active: icon should show moon.
- Night active: icon should show sun.
- Style should match the existing poster icons/stickers.

The poster toggle should update both:

  TuringStoryWindowBundleController
  TuringStoryDoorBundleController

Recommended coordinator shape:

  @MainActor
  private func setStoryOpeningAtmosphere(_ atmosphere: PortalHDRIAtmosphere) async {
      currentStoryWindowAtmosphere = atmosphere
      await turingWindowBundleController?.setAtmosphere(atmosphere)
      await turingDoorBundleController?.setAtmosphere(atmosphere)
      updateTuringWindowDayNightIcon()
  }

If naming is cleaned up, rename the icon update to:

  updateTuringStoryDayNightIcon()

but do not change behavior for the window.


Occupancy And Poster Avoidance
------------------------------
Door should register wall occupancy like the window and shelf.

If WallPropOccupancyRegistry uses an enum, add:

  storyDoorBundle

Door occupancy should include:

- width + occupancyPaddingMeters
- height + occupancyPaddingMeters
- same wall-space rect as resolved DoorPlacement

Avoid:

- poster
- walkie shelf bundle
- Story window bundle
- Horde/Story portals
- existing door/window occupancy records

Door placement should prefer a wall position that leaves enough floor clearance and does not overlap the poster icon area.

Acceptance Checklist
--------------------
- Door appears on wall.
- Door bottom is snapped to detected floor.
- Door does not float at window height.
- Door does not overlap poster, walkie shelf, or Story window.
- Door portal plane shows the day/night portal world.

Implementation Warning
----------------------
The tempting wrong implementation is to copy the Story window placement and change names only. Do not do that. The door is not an elevated wall prop. The door must reuse floor-locked DoorPlacement behavior and the Horde ground-disc height.

The other tempting wrong implementation is to use the old window ground-disc offset. Do not do that. The exterior ground disc should be at:

  context.floorY + 0.004

matching the Horde portal MVP.
