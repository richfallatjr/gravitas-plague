Turing Playback Rebuild Handoff
================================

Repo:

Current HEAD observed by Codex:
  3debe21 Occlusion card MVP

Purpose:
  Replace the current Story/Turing playback ownership layer. Do not change the
  LLM prompts, audiobook sectioning, Qwen model, Big Mike clone profile, filler
  assets, wall bundle placement, or TTS generation code unless needed only to
  connect to the new playback event API.

Required behavior from product owner:
  1. Exactly one mandatory Big Mike filler clip before initial generated speech.
  2. Generated TTS clips play sequentially, in segment order, beginning to end.
  3. No duration estimates, sleeps, or fallback timers may advance generated
     playback. Completion must come from actual playback completion.
  4. If no generated playback is ready, play filler according to filler policy.
  5. Insert random dead air between filler clips. Dead air is not audio.
  6. If generated playback becomes ready during filler, finish current filler.
  7. If generated playback becomes ready during dead air, cancel dead air and
     start generated playback immediately.
  8. All Story/Turing generated speech, filler, and static must originate from
     the walkie talkie spatial emitter.
  9. Playback must not stomp dictation, microphone recording, or screen capture
     audio session state.
 10. Preserve the two fresh Qwen MLX instance generation pipeline and keep both
     instances running concurrently. Playback must not wait for all generation.

Replacement Architecture
------------------------

Create one active owner:

  TuringStoryWalkiePlaybackCoordinator

Responsibilities:
  - Own runID.
  - Own nextPlaybackSegmentIndex.
  - Own pending generated WAVs by segmentIndex.
  - Own skipped segment indexes.
  - Own active generated/filler/dead-air state.
  - Own mandatory first filler counter.
  - Own compute-in-flight set.
  - Own all-compute-finished flag.
  - Own waitUntilPlaybackFinished continuations.
  - Decide what plays next.
  - Never let any other class advance generated playback.

Low-level helper:

  TuringWalkieOneShotClipPlayer

Responsibilities:
  - Given a file URL and kind, play exactly one file from the walkie emitter.
  - Attach generated and filler one-shots under the walkie emitter.
  - Retain the RealityKit AudioPlaybackController and child entity until actual
    completion.
  - Report completion through AudioPlaybackController.completionHandler for the
    exact handle.
  - Never call stop except explicit coordinator cancel/shutdown.
  - Never know nextPlaybackSegmentIndex.
  - Never clean generated WAV files.

Static helper:

  TuringWalkieStaticLoopController

Responsibilities:
  - Play static loop from the same walkie emitter.
  - Static may overlap generated/filler if desired.
  - Static must not stop generated/filler.
  - Generated/filler must not stop static except explicit stop/cancel.

Generated WAV writer:

  Keep or replace TuringGeneratedWAVWriter/TuringAudioFileWriter if correct.
  Generated samples must be written as:
    segment_000N.tmp.wav
    close file
    move to segment_000N.wav
    reopen final file and validate nonzero frame count/duration
  Cleanup only after actual generated clip completion.

Required State Machine
----------------------

State:
  runActive: Bool
  runID: String?
  expectedSegmentCount: Int?
  nextPlaybackSegmentIndex: Int
  activeComputeSegments: Set<Int>
  pendingGenerated: [Int: GeneratedClip]
  skippedSegments: Set<Int>
  allComputeFinished: Bool
  activeItem: ActiveItem
  firstPrerollRemaining: Int
  lastFillerURL: URL?
  deadAirTask: Task<Void, Never>?

ActiveItem:
  none
  generated(segmentIndex: Int, handleID: UUID, fileURL: URL)
  filler(handleID: UUID, fileURL: URL)
  deadAir(id: UUID)
  cancelled

Policy:
  firstSegmentPrerollFillerCount = 1
  chainFillerWhileComputeWithoutSpeech = true
  completeCurrentFillerBeforeGeneratedSpeech = true
  deadAirAfterFillerEnabled = true
  deadAirMinSeconds = 0.5
  deadAirMaxSeconds = 4.0
  avoidImmediateFillerRepeat = true

Important policy interpretation:
  - Exactly one filler is mandatory before first generated playback.
  - Additional filler before first generated playback is allowed only if the
    generated segment is still not ready after that filler and a dead-air period.
  - There is no mandatory filler between generated segments when the next
    generated segment is already ready.
  - If generated segment N+1 is not ready after generated segment N completes,
    filler/dead-air cycles bridge the gap.
  - If generated becomes ready while filler is playing, do not interrupt filler.
  - If generated becomes ready while dead air is active, cancel dead air and
    start generated immediately.

Reconcile Algorithm
-------------------

Pseudo-code:

  reconcile(reason):
    guard runActive else return
    guard activeItem == .none else return

    while skippedSegments contains nextPlaybackSegmentIndex:
      remove skip
      nextPlaybackSegmentIndex += 1

    if firstPrerollRemaining > 0:
      if pendingGenerated[nextPlaybackSegmentIndex] != nil ||
         activeComputeSegments.isEmpty == false:
        firstPrerollRemaining -= 1
        startFiller(reason: "firstSegmentPreroll")
        return

    if let generated = pendingGenerated.removeValue(forKey: nextPlaybackSegmentIndex):
      startGenerated(generated)
      return

    if activeComputeSegments.isEmpty == false:
      startFiller(reason: "computeWithoutSpeech")
      return

    if allComputeFinished && no pending/skipped/active:
      finishRun()

Generated completion:

  generatedDidComplete(handleID, segmentIndex):
    guard activeItem == .generated(segmentIndex, handleID, fileURL) else:
      log stale completion
      return
    cleanup fileURL
    activeItem = .none
    nextPlaybackSegmentIndex = segmentIndex + 1
    reconcile("generatedComplete")

Filler completion:

  fillerDidComplete(handleID):
    guard activeItem == .filler(handleID, fileURL) else:
      log stale completion
      return
    activeItem = .none
    if pendingGenerated[nextPlaybackSegmentIndex] != nil:
      reconcile("fillerCompleteGeneratedReady")
    else if activeComputeSegments.isEmpty == false && deadAirAfterFillerEnabled:
      startDeadAir()
    else:
      reconcile("fillerComplete")

Dead air:

  startDeadAir():
    id = UUID()
    activeItem = .deadAir(id)
    seconds = Double.random(in: 0.5...4.0)
    sleep seconds in cancellable task

  qwenComputeFinished(...):
    write/validate generated WAV
    pendingGenerated[segmentIndex] = wav
    if activeItem is deadAir:
      cancel deadAirTask
      activeItem = .none
    reconcile("computeFinished")

Low-Level Spatial Clip Player Contract
--------------------------------------

API:

  @MainActor
  final class TuringWalkieOneShotClipPlayer {
      func playOneShot(
          fileURL: URL,
          kind: ClipKind,
          label: String,
          completion: @escaping @MainActor (UUID) -> Void
      ) throws -> UUID

      func cancel(handleID: UUID, reason: String)
      func cancelAll(reason: String)
  }

Rules:
  - For generated and filler, create a fresh child entity under:
      TuringStoryWalkieTalkie_AudioEmitter
    or stable child lanes under that emitter.
  - Set SpatialAudioComponent on child entity.
  - Use AudioFileResource.load(... shouldLoop: false).
  - Call entity.playAudio(resource).
  - Retain AudioPlaybackController and entity in dictionaries by handleID.
  - Set controller.completionHandler before returning if possible.
  - In completion handler:
      remove handle from retained dictionaries
      remove transient child entity
      call completion(handleID)
  - Do not use file duration to report completion.
  - Do not call stop for normal completion.
  - Do not stop any other handle when starting a new handle.

If RealityKit completion is not reliable enough:
  The architect must implement an AVAudioEngine spatial node route that is
  still attached to walkie world position and exposes actual node completion.
  Do not fall back to non-spatial AVAudioPlayer for Story runtime unless this
  is explicitly accepted as a temporary diagnostic path.

Two Fresh Qwen Instance Contract
--------------------------------

Playback rebuild must preserve this generation shape:

  let freshPool = try TuringQwenNativeGenerationSchedulerFactory.makeFresh2Pool()
  try await freshPool.warmLoadExactlyRequestedInstances(...)
  let scheduler = TuringQwenNativeGenerationSchedulerFactory.makeFresh2Scheduler(
      instancePool: freshPool
  )
  let report = try await scheduler.renderSegments(
      requests,
      runID: runID,
      skipSegmentFailures: true,
      onSegmentStarted: { _, segmentIndex in
          await playback.qwenComputeStarted(segmentIndex: segmentIndex)
      },
      onSegmentFinished: { generated in
          await playback.qwenComputeFinished(
              segmentIndex: generated.segmentIndex,
              audio: TuringComputeGapGeneratedAudio(...)
          )
      },
      onSegmentSkipped: { skipped in
          await playback.qwenComputeSkipped(
              segmentIndex: skipped.segmentIndex,
              reason: skipped.errorDescription
          )
      }
  )
  await playback.qwenComputeAllFinished()
  await playback.waitUntilPlaybackFinished()

Rules:
  - Do not wait for all Qwen segments before starting playback.
  - Do not block scheduler workers on playback.
  - Segment 0 starts playback as soon as segment 0 is ready and mandatory
    first filler has completed.
  - Segments 1...N may finish out of order; playback still consumes only
    nextPlaybackSegmentIndex.
  - Scheduler remains concurrent with exactly two fresh Qwen instances.

------------------

  - TuringNativeQwenHelloWorldCanary creates TuringSerialWAVFillerPlaybackQueue.
  - Active generated playback references TuringComputeGapAudioCoordinator.
  - Any active generated playback path uses fallbackDuration.
  - Any active generated playback path uses Task.sleep to advance generated
    playback.
  - Turing playback code calls AVAudioSession.setCategory(.playback).
  - More than one generated playback owner is wired to active Story/Turing routes.

Runtime audit should verify:
  - Segment 0 generated ready does not start until exactly one mandatory filler
    has completed.
  - Segment N+1 never starts before segment N completion.
  - A filler clip cannot interrupt generated speech.
  - Generated-ready during filler waits for filler completion.
  - Generated-ready during dead air cancels dead air and starts generated.
  - Static, if enabled, comes from the walkie emitter and does not stop the
    generated/filler queue.
  - Dictation can record while playback/static exist without audio session
    category switching to playback.
  - Two Qwen fresh instances are warmed and used concurrently.
