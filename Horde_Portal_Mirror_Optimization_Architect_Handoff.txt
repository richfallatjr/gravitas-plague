Horde Portal Mirror Optimization Architect Handoff

Goal
----
Reduce M2 stutter and memory pressure from retained portal render mirrors after enemies exit portals.

The heavy object is not the normal gameplay enemy. It is the portal-world render mirror created by
HordePortalSkinnedRenderMirror inside HordePortalInstancedIngressController.

Current implementation:

- HordePortalSkinnedRenderMirror clones source.rootEntity recursively.
- The mirror is parented under the portalWorldRoot.
- The mirror strips gameplay/audio components, but it still carries a cloned skinned hierarchy.
- The mirror receives jointTransforms copied from the source skinned model.
- After ingress completes, PlagueImmersiveCoordinator moves the ingress controller from:

  activeIngressControllers

  to:

  retainedPortalMirrorControllersByEnemyID

- syncAllPortalMirrorsAfterEnemyAnimations() then continues to update both active ingress mirrors and retained mirrors.
- When the enemy is fully on the room side, the mirror becomes hidden but retained.
- It can be re-enabled if the enemy falls back through/near the portal.

That retained fallback behavior is visually nice, but it means every active enemy may carry:

1. the real-world gameplay character entity
2. a portal-world cloned render mirror

By wave 6, this can double the skinned hierarchy count and cause avoidable stutter.

Desired behavior
----------------
Keep portal ingress visuals intact while the enemy is emerging.

For wave 1-5:
- Preserve current mirror behavior unless profiling says otherwise.
- Retained portal fallback may stay enabled.

For wave 6+ or wave > 5:
- Do not retain the portal render mirror after ingress exit.
- As soon as the enemy reaches realWorldFollowing / ingress complete, cleanup the portal mirror.
- The gameplay enemy remains alive in the room.
- The portal visual instance is destroyed/removed.
- If the enemy falls back into the portal later, accept that there is no mirrored fallback for these high waves.

Optional additional throttle:
- If any retained mirror still exists, do not sync hidden retained mirrors every frame.
- Hidden retained mirrors should either:
  - not update at all until close to re-enable threshold, or
  - update only every N frames.

Non-goals
---------
- Do not remove the gameplay enemy.
- Do not change portal placement.
- Do not change ingress timing.
- Do not change portal animation.
- Do not change character animation runtime.
- Do not change the room-side entity.
- Do not pool portal mirror clones.
- Do not retain mirrors for high waves just in case.

Implementation plan
-------------------

1. Add an explicit retention policy.

Use a small enum instead of scattered wave checks.

Code:

enum HordePortalMirrorRetentionPolicy: String {
    case retainAfterExit
    case destroyAfterExit
}

private enum HordePortalMirrorOptimizationSettings {
    static let destroyMirrorAfterExitStartingWave = 6
    static let retainedHiddenMirrorSyncIntervalFrames = 12

    static func retentionPolicy(
        wave: Int
    ) -> HordePortalMirrorRetentionPolicy {
        wave >= destroyMirrorAfterExitStartingWave
            ? .destroyAfterExit
            : .retainAfterExit
    }
}


2. Pass the policy into HordePortalInstancedIngressController.

Current call site is inside registerHordeEnemyForInstancedPortalIngress(...):

let ingress = try HordePortalInstancedIngressController(
    enemy: controller,
    portal: portal,
    sceneRoot: sceneRoot,
    side: side
)

Patch to:

let mirrorRetentionPolicy = HordePortalMirrorOptimizationSettings.retentionPolicy(
    wave: wave
)

let ingress = try HordePortalInstancedIngressController(
    enemy: controller,
    portal: portal,
    sceneRoot: sceneRoot,
    side: side,
    mirrorRetentionPolicy: mirrorRetentionPolicy
)

print("""
[HordePortalMirror] retention policy selected
  wave: \(wave)
  enemyID: \(id)
  policy: \(mirrorRetentionPolicy.rawValue)
""")


3. Store the policy in HordePortalInstancedIngressController.

Add property:

private let mirrorRetentionPolicy: HordePortalMirrorRetentionPolicy

Add init parameter:

init(
    enemy: JockRetargetTestController,
    portal: HordePortal,

    mirrorRetentionPolicy: HordePortalMirrorRetentionPolicy = .retainAfterExit

    self.mirrorRetentionPolicy = mirrorRetentionPolicy

}

Expose:

var shouldRetainPortalMirrorAfterExit: Bool {
    mirrorRetentionPolicy == .retainAfterExit
}

var shouldDestroyPortalMirrorAfterExit: Bool {
    mirrorRetentionPolicy == .destroyAfterExit
}


4. Cleanup mirror at ingress completion for high waves.

Current PlagueImmersiveCoordinator.updatePortalIngressControllers(...) flow:

case .realWorldFollowing:
    retainedIDs.append(enemyID)
    finishedIDs.append(enemyID)

Then later:

for enemyID in retainedIDs {
    guard let ingress = activeIngressControllers[enemyID],
          ingress.portalMirrorRetainedAfterExit else {
        continue
    }

    retainedPortalMirrorControllersByEnemyID[enemyID] = ingress
}

Patch to split retention and destruction:

case .realWorldFollowing:
    if ingress.shouldRetainPortalMirrorAfterExit {
        retainedIDs.append(enemyID)
    } else {
        ingress.cleanupPortalMirror(
            reason: "mirror_destroyed_after_ingress_wave_cap"
        )

        print("""
        [HordePortalMirror] destroyed after ingress exit
          enemyID: \(enemyID)
          reason: high_wave_memory_cap
          gameplayEnemyStillAlive: true
          retainedFallback: false
        """)
    }

    finishedIDs.append(enemyID)

Then keep the existing retainedIDs loop for low-wave mirrors only:

for enemyID in retainedIDs {
    guard let ingress = activeIngressControllers[enemyID],
          ingress.shouldRetainPortalMirrorAfterExit,
          ingress.portalMirrorRetainedAfterExit else {
        continue
    }

    retainedPortalMirrorControllersByEnemyID[enemyID] = ingress
}

Result:
- Active ingress mirrors still exist during portal emergence.
- High-wave mirrors are destroyed the moment ingress completes.
- High-wave ingress controllers are removed from activeIngressControllers and not added to retainedPortalMirrorControllersByEnemyID.


5. Do not sync retained hidden mirrors every frame.

Current syncAllPortalMirrorsAfterEnemyAnimations() syncs:

for ingress in activeIngressControllers.values {
    ingress.updatePortalMirrorAfterSourceAnimation()
}

for ingress in retainedPortalMirrorControllersByEnemyID.values {
    ingress.updatePortalMirrorAfterSourceAnimation()
}

This means retained mirrors, even hidden retained mirrors, still run visibility / pose sync logic every frame.

Patch:

private var portalMirrorSyncFrameIndex = 0

private func syncAllPortalMirrorsAfterEnemyAnimations() {
    portalMirrorSyncFrameIndex += 1

    for ingress in activeIngressControllers.values {
        ingress.updatePortalMirrorAfterSourceAnimation()
    }

    let shouldSyncRetainedThisFrame =
        portalMirrorSyncFrameIndex %
        HordePortalMirrorOptimizationSettings.retainedHiddenMirrorSyncIntervalFrames == 0

    for ingress in retainedPortalMirrorControllersByEnemyID.values {
        switch ingress.portalMirrorVisibilityState {
        case .visiblePortalSideOrCrossing:
            // Visible retained mirrors must still match the source.
            ingress.updatePortalMirrorAfterSourceAnimation()

        case .hiddenRoomSideRetained:
            // Throttle hidden retained mirrors. They are not visible.
            if shouldSyncRetainedThisFrame {
                ingress.updatePortalMirrorAfterSourceAnimation()
            }

        case .cleanedUp, nil:
            break
        }
    }

    updatePortalMirrorCounters()
}

private func updatePortalMirrorCounters() {
    let allMirrorControllers =
        Array(activeIngressControllers.values) +
        Array(retainedPortalMirrorControllersByEnemyID.values)

    let visibleCount = allMirrorControllers.filter {
        $0.portalMirrorVisibilityState == .visiblePortalSideOrCrossing
    }.count

    let hiddenRetainedCount = allMirrorControllers.filter {
        $0.portalMirrorVisibilityState == .hiddenRoomSideRetained
    }.count

    timingProfiler.setCounter(
        "portal_mirror.visible_or_crossing.count",
        visibleCount
    )

    timingProfiler.setCounter(
        "portal_mirror.hidden_retained.count",
        hiddenRetainedCount
    )
}


6. Optional: make hidden retained mirror logic cheaper inside HordePortalSkinnedRenderMirror.

Current hidden retained logic calls syncRootTransformOnly() every frame:

case .hiddenRoomSideRetained:
    syncRootTransformOnly()

    if signedDistance <= visibilityPolicy.showAtOrBelowRoomSideDistance {
        syncCompletePoseAndTransform()
        rootEntity.isEnabled = true
        visibilityState = .visiblePortalSideOrCrossing
    }

For low waves, this is acceptable. If still expensive, add a method that checks only body distance before syncing root/joints:

func updateHiddenRetainedVisibilityOnly(
    sourceBodyCenterWorld: SIMD3<Float>
) {
    guard !hasCleanedUp else { return }
    guard visibilityState == .hiddenRoomSideRetained else { return }

    let signedDistance = portalPlane.signedRoomSideDistance(
        worldPosition: sourceBodyCenterWorld
    )

    guard signedDistance <= visibilityPolicy.showAtOrBelowRoomSideDistance else {
        return
    }

    syncRootTransformOnly()
    syncCompletePoseAndTransform()
    rootEntity.isEnabled = true
    visibilityState = .visiblePortalSideOrCrossing

    print("""
    [HordePortalMirror] re-enabled for fallback
      sourceEnemyID: \(sourceEnemyID)
      mirrorID: \(id)
      portalID: \(portalID)
      signedRoomDistance: \(signedDistance)
      poseSyncedBeforeReveal: true
    """)
}

Then coordinator can call visibility-only checks for hidden retained mirrors on throttled frames.

Acceptance criteria
-------------------

- Normal portal ingress visuals are unchanged.
- The portal render mirror exists while the enemy is inside/crossing the portal.
- For wave 1-5, retained fallback behavior remains available.
- For wave 6+, portal render mirror is destroyed immediately after ingress completes.
- For wave 6+, retainedPortalMirrorControllersByEnemyID does not grow with active enemies.
- The gameplay enemy is not removed when the mirror is destroyed.
- The real-world enemy continues walking/attacking normally after exit.
- No second animation runtime is created.
- No dirty gameplay clone pooling is introduced.
- Stutter improves once the active on-screen count approaches six.


Risk / tradeoff
---------------

The visual tradeoff is intentional:

For wave 6+, if a character physically falls back into the portal after exiting, the portal-world mirror will no longer be there to render the fallback correctly.

That is acceptable for the M2 performance cap because it prevents every active enemy from carrying a second skinned render hierarchy after ingress.

If this visual fallback becomes important later, use a bounded budget instead of full retention:

static let maxRetainedMirrorsAfterExit = 1

Keep only the most recently exited mirror or the mirror nearest the player/portal, and destroy the rest.
