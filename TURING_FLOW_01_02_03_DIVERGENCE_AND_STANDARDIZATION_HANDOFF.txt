======================================================================
1. PURPOSE
======================================================================

This handoff documents why ScriptPoint01 is the only proven Turing Flow,
why ScriptPoint02 and ScriptPoint03 are not standardized copies of that
flow, whether 02/03 use Fresh2, why ScriptPoint03 can sound like its PR is
repeated, and how to replace all point-specific orchestration with one
data-driven engine that supports an unlimited number of script points and
voice clones.

This is an architecture and implementation handoff. It does not authorize
changes to room scanning, room placement, wall layout, portals, props,
Foundation prompt wording, clone artifacts, Qwen internals, or audio assets.

2. EXECUTIVE VERDICT
======================================================================

2.1 Does ScriptPoint02 use Fresh2?

Yes.

The active call chain is:

  TuringScriptPoint02And03FlowController
    -> TuringRichQwenRenderer
    -> TuringBaseCloneCharacterRenderer(character: .rich)
    -> TuringQwenNativeGenerationSchedulerFactory.makeFresh2Pool()
    -> warmLoadExactlyRequestedInstances(...)
    -> makeFresh2Scheduler(instancePool:)
    -> scheduler.renderSegments(...)

The runtime logs confirm:

  [TuringQwenFresh2] pool ready
    requestedInstanceCount: 2
    actualInstanceCount: 2
    sharedWeights: false
    fallbackUsed: false

2.2 Does ScriptPoint03 use Fresh2?

Yes, when its Foundation plan succeeds and its renderer task reaches Qwen.

The active call chain is:

  TuringScriptPoint02And03FlowController
    -> TuringBigMikeQwenRenderer
    -> TuringBaseCloneCharacterRenderer(character: .bigMike)
    -> makeFresh2Pool()
    -> makeFresh2Scheduler(instancePool:)
    -> scheduler.renderSegments(...)

2.3 Is 02/03 implemented using the same Turing Flow machinery as 01?

No.

ScriptPoint01 delegates the PR + Foundation + Fresh2 + playback lifecycle to
an existing reusable function:

  TuringNativeQwenHelloWorldCanary.runVoicePromptAfterPrerecording(...)

ScriptPoint02 and ScriptPoint03 reimplement that lifecycle manually inside a
single 600-line point-specific actor:

  TuringScriptPoint02And03FlowController

That controller manually owns two descriptors, two prerecordings, two
Foundation tasks, two renderer tasks, two playback coordinators, comm SFX,
seed updates, delays, progression, error reconciliation, and cancellation.

The result is not three instances of one workflow. It is one established
workflow plus a second custom workflow that happens to contain two points.

2.4 Why can ScriptPoint03 sound like it plays the PR twice?

The current ScriptPoint03 code queues the authored PR audio once. There is no
second enqueuePrerecording call inside the local ScriptPoint03 block.

However, it constructs this Foundation context:

  let bigMikeContext = """
    RICH AUTHORED OUTGOING PR:
    \(richPrerecording.transcript)

    RICH GENERATED CONTINUATION:
    \(generatedRichTranscript)

    BIG MIKE AUTHORED PR THAT WILL PLAY BEFORE HIS GENERATED CONTINUATION:
    \(bigMikePrerecording.transcript)
    """

It then passes that entire value as prerecordingTranscript for the Big Mike
voicePrompt. The shared prompt says not to repeat recent context, but does not
make the authored PR a structured, immutable "already spoken" field. The
Foundation response can therefore restate the authored PR. Qwen then renders
that restatement, producing the audible effect of PR -> same PR again.

There is a second possible duplication class: the combined controller can be
invoked automatically through TuringScriptPointProgressionController or
manually through TuringEpisodePickerView. The controller's running flag blocks
simultaneous calls, but a later invocation can replay both points. Existing
logs do not provide a single flowInstanceID across every event, so this cannot
be distinguished from generated-text repetition by ear alone.

The architect must instrument both identities:

  flowInstanceID
  scriptPointID
  prerecordingPlaybackHandleID
  Foundation response segment text
  generated playback segment text hash

Do not claim duplicate audio enqueue unless two distinct prerecording handle
IDs are observed for the same flowInstanceID and scriptPointID.

======================================================================
7. ROOT DISEASE
======================================================================

The root disease is orchestration duplication.

The project has reusable low-level parts:

  - Foundation dialogue service
  - prerecording store
  - character profile store
  - clone profile loader
  - Fresh2 pool and scheduler
  - generated segment callbacks
  - actual-completion playback coordinator
  - filler policy
  - comm SFX controller
  - seed store

But there is no single production TuringFlow engine that composes those parts.
Each milestone therefore creates a new orchestration path. That produces:

  1. Different compute overlap timing.
  2. Different failure cleanup.
  3. Different PR preservation rules.
  4. Different filler behavior.
  5. Different route selection.
  6. Different progression semantics.
  7. Different seed keys.
  8. Different logging.
  9. Point-specific retry behavior.
 10. No scalable path for ScriptPoint04 or a third character.

Patching ScriptPoint02And03FlowController cannot solve this structurally. It
can only make one hardcoded pair behave better.

======================================================================
8. REQUIRED STANDARDIZED TURING FLOW
======================================================================

Every prerecording-driven Turing Flow must be the same state machine:

  load descriptor
    -> resolve character runtime
    -> create one flowInstanceID
    -> start optional pre-roll SFX
    -> start Foundation Task
    -> queue and play PR immediately
    -> while PR plays, await Foundation and begin Fresh2 when plan is ready
    -> publish Qwen outputs to the same playback run
    -> after PR, bridge with the configured filler policy
    -> play generated segments in order to actual completion
    -> play optional post-roll SFX
    -> update conversation seed
    -> open or close the interaction gate
    -> dispatch generic nextScriptPointID

No ScriptPoint-specific Swift orchestration is allowed.

The only point-specific inputs are data:

  - prerecordingID
  - response prompt ID
  - character ID
  - output route
  - filler profile
  - pre/post SFX policy
  - delay/lead-in policy
  - conversation key
  - next point
  - interaction gate after completion

10. CHARACTER RUNTIME REGISTRY
======================================================================

The current renderer has a closed enum:

  enum Character {
      case rich
      case bigMike
  }

That does not support an episodic game with unlimited clone voices. Replace it
with a registry keyed by characterID.

  struct TuringCharacterRuntimeDefinition: Sendable {
      let characterID: String
      let displayName: String
      let voiceID: String
      let outputProcessingPolicy: TuringQwenOutputProcessingPolicy
      let fillerDirectoryCandidates: [String]
      let generatedGainDB: Float
      let prerecordingGainDB: Float
      let fillerGainDB: Float
      let cloneProfileLoader: @Sendable (URL) throws
          -> TuringQwenNativeCloneProfile
  }

  struct TuringCharacterRuntimeRegistry: Sendable {
      private let definitions: [String: TuringCharacterRuntimeDefinition]

      func require(_ characterID: String)
          throws -> TuringCharacterRuntimeDefinition
      {
          guard let definition = definitions[characterID] else {
              throw TuringRuntimeError.invalidConfig(
                  "No Turing character runtime for \(characterID)."
              )
          }
          return definition
      }
  }

The generic renderer accepts a runtime definition. It does not switch on Rich
or Big Mike:

  actor TuringCharacterQwenRenderer {
      private let runtime: TuringCharacterRuntimeDefinition
      private let resources: TuringBaseCloneRuntimeResources
      private let arbiter: TuringQwenCharacterPoolArbiter

      func render(
          segments: [TuringSpeechSegment],
          runID: String,
          sink: any TuringGeneratedSegmentSink
      ) async throws {
          await arbiter.acquire(owner: "\(runtime.characterID).\(runID)")
          defer {
              Task {
                  await arbiter.release(
                      owner: "\(runtime.characterID).\(runID)"
                  )
              }
          }

          let bundleRoot = try requireBundleRoot()
          let profile = try runtime.cloneProfileLoader(bundleRoot)
          let stagedModel = try resources.stageWritableModel(
              from: resources.locateBundledModel()
          )

          let pool = try TuringQwenNativeGenerationSchedulerFactory
              .makeFresh2Pool()
          defer {
              Task {
                  await pool.unloadAll(reason: "flowFinished.\(runID)")
              }
          }

          try await pool.warmLoadExactlyRequestedInstances(
              modelRoot: stagedModel,
              cloneProfile: profile,
              variantID: profile.defaultVariantID,
              performanceMode: .performance
          )

          let scheduler = TuringQwenNativeGenerationSchedulerFactory
              .makeFresh2Scheduler(instancePool: pool)
          let requests = makeRequests(
              segments: segments,
              profile: profile
          )

          _ = try await scheduler.renderSegments(
              requests,
              runID: runID,
              skipSegmentFailures: true,
              onSegmentStarted: { _, index in
                  await sink.computeStarted(index: index)
              },
              onSegmentFinished: { result in
                  await sink.computeFinished(
                      index: result.segmentIndex,
                      audio: .init(
                          segmentIndex: result.segmentIndex,
                          samples: result.audio.samples,
                          sampleRate: Double(result.audio.sampleRate),
                          channelCount: 1
                      )
                  )
              },
              onSegmentSkipped: { skipped in
                  await sink.computeSkipped(
                      index: skipped.segmentIndex,
                      reason: skipped.errorDescription
                  )
              }
          )
      }
  }

Do not use detached defer Tasks exactly as shown without reviewing actor
lifetime and structured cleanup. The important contract is one generic
renderer and guaranteed pool unload/release on every exit.

11. ONE PRODUCTION TURING FLOW ENGINE
======================================================================

Add one actor:

  actor TuringFlowEngine {
      static let shared = TuringFlowEngine(...)

      private var activeFlow: ActiveFlow?
      private var completedScriptPointIDs = Set<String>()

      func run(
          scriptPointID: String,
          trigger: TuringFlowTriggerSource
      ) async -> TuringFlowResult
  }

Core implementation shape:

  func run(
      scriptPointID: String,
      trigger: TuringFlowTriggerSource
  ) async -> TuringFlowResult {
      let descriptor = try descriptorStore.require(scriptPointID)
      let flowInstanceID = UUID()

      guard activeFlow == nil else {
          return .ignored(.anotherFlowActive)
      }

      activeFlow = ActiveFlow(
          flowInstanceID: flowInstanceID,
          scriptPointID: scriptPointID,
          state: .loading
      )
      defer { activeFlow = nil }

      do {
          let prerecording = try prerecordingStore.descriptor(
              id: descriptor.transmission.prerecordingID
          )
          let prerecordingURL = try prerecordingStore.audioURL(
              for: prerecording
          )
          let prompt = try voicePromptStore.descriptor(
              id: descriptor.transmission.voicePromptID
          )
          let runtime = try characterRegistry.require(
              descriptor.transmission.characterID
          )

          try validateIdentity(
              descriptor: descriptor,
              prerecording: prerecording,
              prompt: prompt,
              runtime: runtime
          )

          let playback = await playbackFactory.make(
              descriptor: descriptor,
              character: runtime,
              flowInstanceID: flowInstanceID
          )

          await interactionGate.setBusy(
              true,
              owner: flowInstanceID
          )
          defer {
              Task {
                  await interactionGate.setBusy(
                      false,
                      owner: flowInstanceID
                  )
              }
          }

          if descriptor.transmission.commSFX.openBeforePrerecording {
              try await commSFX.playScriptedOpenComm(
                  reason: "flow.\(flowInstanceID).open"
              )
          }

          let planTask = Task {
              try await dialogueService.generateVoicePrompt(
                  makeVoicePromptRequest(
                      descriptor: descriptor,
                      prerecording: prerecording,
                      prompt: prompt
                  )
              )
          }

          await playback.beginRun(
              runID: flowInstanceID.uuidString,
              expectedSegmentCount: nil
          )
          await playback.enqueuePrerecording(
              id: prerecording.prerecordingID,
              fileURL: prerecordingURL
          )

          let completionTask = Task {
              await playback.waitUntilPlaybackFinished()
          }

          let plan = try await planTask.value
          await playback.setExpectedGeneratedSegmentCount(
              plan.segments.count
          )
          await seedStore.updateSeed(
              plan.conversationSeed,
              for: descriptor.transmission.conversationKey
          )

          let renderer = rendererFactory.make(runtime: runtime)
          do {
              try await renderer.render(
                  segments: plan.segments,
                  runID: flowInstanceID.uuidString,
                  sink: playback
              )
              await playback.qwenComputeAllFinished()
          } catch {
              await playback.qwenComputeFailed(
                  expectedSegmentCount: plan.segments.count,
                  reason: error.localizedDescription
              )
              throw error
          }

          await completionTask.value

          if descriptor.transmission.commSFX.sendAfterGenerated {
              try await commSFX.playScriptedSendComm(
                  reason: "flow.\(flowInstanceID).send"
              )
          }

          completedScriptPointIDs.insert(scriptPointID)
          await applyCompletionGate(descriptor.progression)

          if descriptor.progression.automaticAdvance,
             let next = descriptor.progression.nextScriptPointID {
              return await runNextAfterCurrentUnwinds(
                  next,
                  parentFlowInstanceID: flowInstanceID
              )
          }

          return .succeeded(scriptPointID)
      } catch {
          return await finishFailedFlowWithoutCuttingActiveMedia(
              flowInstanceID: flowInstanceID,
              scriptPointID: scriptPointID,
              error: error
          )
      }
  }

Important implementation note:

The recursive run shown above must not execute while activeFlow still owns the
current point. In production, queue nextScriptPointID and let a serial episode
coordinator start it after the current engine call releases ownership.

12. PR CONTEXT MUST BE STRUCTURED
======================================================================

Do not concatenate multiple speakers and an authored outgoing PR into one
untyped prerecordingTranscript string.

Replace:

  let bigMikeContext = """
    RICH AUTHORED OUTGOING PR:
    ...
    RICH GENERATED CONTINUATION:
    ...
    BIG MIKE AUTHORED PR THAT WILL PLAY BEFORE HIS GENERATED CONTINUATION:
    ...
  """

With:

  struct TuringVoicePromptContext: Codable, Sendable {
      let dialogueHistory: [Turn]
      let authoredPrerecording: AuthoredPrerecording

      struct Turn: Codable, Sendable {
          let speakerID: String
          let text: String
          let source: Source
      }

      struct AuthoredPrerecording: Codable, Sendable {
          let prerecordingID: String
          let speakerID: String
          let transcript: String
          let alreadySpoken: Bool
          let generatedResponseMustContinueAfterIt: Bool
      }
  }

Render it into the Foundation prompt with an explicit contract:

  Authored current-speaker prerecording already played or is playing:
  """
  {{authoredPrerecordingTranscript}}
  """

  Continue after it. Do not restate, paraphrase, summarize, or replay any
  sentence from the authored prerecording. Return only new spoken words.

This is a prompt responsibility, not a runtime semantic failure gate. Log the
raw response and exact TTS inputs so repetition is diagnosable.

======================================================================
13. PLAYBACK OWNERSHIP CONTRACT
======================================================================

One Turing Flow point owns one playback coordinator instance.

The coordinator must own:

  - one prerecording item
  - generated segment ordering
  - filler/dead-air policy
  - exact active playback handle
  - actual completion matching
  - WAV cleanup after completion
  - completion waiters

The engine must never:

  - enqueue the same prerecording twice for one flowInstanceID
  - create a second generated playback owner
  - advance on duration estimates
  - cancel valid PR playback because Foundation or Qwen failed
  - start nextScriptPointID before actual playback completion
  - treat a log message such as microphoneGate=open as an actual UI state

Add idempotency to enqueuePrerecording:

  private var acceptedPrerecordingID: String?

  func enqueuePrerecording(id: String, fileURL: URL) async {
      guard acceptedPrerecordingID == nil else {
          print("[TuringFlow] duplicate prerecording enqueue ignored ...")
          return
      }
      acceptedPrerecordingID = id
      ...
  }

This guard is not a substitute for fixing duplicate flow invocation. It makes
one run locally idempotent and produces evidence.

======================================================================
14. FAILURE CONTRACT
======================================================================

Foundation failure after PR starts:

  - PR continues to actual completion.
  - No generated TTS is expected.
  - Playback run is terminalized with expected count zero.
  - Point result records generatedPlanFailed.
  - Do not call runCancelled on the active PR.

Qwen partial failure:

  - Prepared successful segments play in order.
  - Failed indices are marked skipped.
  - PR and active generated audio are never interrupted.
  - Point result records partialGeneratedFailure.

Qwen total failure:

  - PR completes.
  - Filler does not run forever.
  - Every unresolved expected index is reconciled.
  - Point result records generatedAudioFailed.

Playback backend failure:

  - This is the only media-layer failure allowed to stop the current item.
  - The exact handle, route, source URL, and backend status must be logged.

Progression failure:

  - Completed point remains completed.
  - Next point can be retried by ID.
  - Completed PR/TTS is never replayed implicitly.

19. ARCHITECT SUMMARY
======================================================================

ScriptPoint02 and ScriptPoint03 do use Fresh2. The logs and code confirm two
fresh instances, no shared weights, and no fallback.

They still diverge materially from ScriptPoint01 because they do not use one
shared Turing Flow orchestration engine. They are manually implemented as a
hardcoded pair inside TuringScriptPoint02And03FlowController.

ScriptPoint03 queues its PR file once in the local block. The most concrete
repetition hazard is that the same full authored PR transcript is inserted
into the generated follow-up context, allowing Foundation output to restate it.
Sequential later invocations are also possible and cannot currently be ruled
out without a flowInstanceID in every log.

The correct fix is not another ScriptPoint03 patch. The correct fix is:

  one descriptor format
  one character runtime registry
  one generic Fresh2 character renderer
  one production TuringFlowEngine
  one playback coordinator per point
  one progression owner
  one identity and logging contract

Then ScriptPoint01, ScriptPoint02, ScriptPoint03, and every future episodic
point are data passed through the same machinery.
